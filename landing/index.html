The golden rule

Three states. No fourth way to prove anything.

Every entry in the ledger, on either rail, is exactly one of these — and only a direct query to the real source can move it to the middle one.

FALOU

Claimed

Someone alleged it — a screenshot, a forwarded message, or the owner typing it in by hand. Registered, but weightless on its own.

PROVOU

Proven

A confirmed signature read directly off Solana, or a transaction read directly off the real bank statement via Open Finance. The only state nobody can fake.

NÃO PROVOU

Unproven

Claimed, and the source was actually checked and did not confirm it — a stronger, more specific claim than "we couldn't check."

How it works

Four steps, every time, no exceptions.

Bill a client

A Solana Pay link for a one-time invoice, an on-chain capped delegation for a recurring one, or a claimed Pix receipt.

It starts as FALOU

Every claim is logged immediately — nothing is ever hidden, it just isn't trusted yet.

The source gets checked

A deterministic script queries the chain or the real bank statement directly — never the model's own opinion.

Only a match is stamped

PROVOU if it matches, NÃO PROVOU if the source was checked and it didn't. Nothing else moves the needle.

Custody

The agent never holds an unbounded key.

Three different custody patterns, chosen deliberately — none of them is "the agent can spend whatever it wants."

  • The client always signs directly. For every one-time invoice and every subscription authorization, the only signature that moves or authorizes funds is the client's own wallet. The agent never touches that key.
  • The agent's own key is capped by the Solana program itself. Recurring pulls use a dedicated key that can only call one instruction, within a per-period cap the client set on-chain — verified directly: an attempt to pull above the cap is rejected by the program, not by our code.
  • Supplier payments need a human approval the agent cannot give itself. Tested directly with a real prompt-injection attack — the agent's own attempt to self-approve returns a genuine denial, not a no-op.

Why Brazil first

The hardest version of the problem, not a limitation.

Brazil pairs the world's largest instant-payment system by transaction count with a freshly regulated stablecoin-as-FX regime. Two of these four layers are Brazil-specific adapters — the core is universal.
